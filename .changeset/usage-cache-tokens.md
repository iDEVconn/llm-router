`LlmUsage` now reports prompt-cache tokens. New optional fields: `cacheCreationInputTokens`, `cacheReadInputTokens` and `inputTokensIncludeCache`. They are filled on normal, streaming and aborted-stream (`LlmAbortedError.usage`) results. Claude: `cache_creation_input_tokens` / `cache_read_input_tokens`, reported in addition to `inputTokens` (which stays Anthropic's uncached `input_tokens`). ChatGPT and Grok: `prompt_tokens_details.cached_tokens`. DeepSeek: `prompt_cache_hit_tokens`. Gemini: `cachedContentTokenCount`. For these four, `inputTokens` already includes the cached tokens, so `inputTokensIncludeCache: true` is set. The fields are omitted when the provider reports nothing. `inputTokens` keeps its old meaning for every provider.

New `splitInputTokens(usage)` returns disjoint uncached / cache-write / cache-read / total input counts for any provider. `PricingTable` entries accept optional `cacheWritePer1M` / `cacheReadPer1M`, and `calculateCost` / `withBudget` price the cache tokens at those rates, falling back to `inputPer1M`. A usage without cache fields costs exactly the same as before. Claude cache rates are per model (https://platform.claude.com/docs/en/about-claude/pricing): 5-minute cache write 1.25x input (the only TTL this package requests); cache read 0.1x input by default, 0.05x on Opus 5.5 / Sonnet 5.5, 0.025x on Fable / Mythos 5.1 and 5.2.

**Claude budgets now see higher costs.** Because Claude results now carry their cache tokens, `maxCostPerCall`, `maxCostTotal` and `onCost` in `withBudget` (and `calculateCost`) now include tokens that were left out before. Add `cacheWritePer1M` / `cacheReadPer1M` to your Claude pricing entries to price them exactly. Without them, cache reads are priced at the full input rate (a conservative over-estimate, 10-40x the real read price) and 5-minute writes at 0.8x their real price. Example, `claude-sonnet-4-5` with a 50k-token cached system prompt read, 1k input and 1k output: $0.018 before, $0.168 now with an old table, $0.033 with the cache rates (true cost). A `maxCostPerCall: 0.05` that used to pass can now throw `BudgetExceededError` after the call was already paid for.

**Usage objects gain fields.** ChatGPT and Grok usage objects now often carry `cacheReadInputTokens: 0` and `inputTokensIncludeCache: true` (OpenAI returns `prompt_tokens_details.cached_tokens: 0` on uncached calls); DeepSeek and Gemini set them when the provider reports a cache count, and Claude sets `cacheCreationInputTokens` / `cacheReadInputTokens` (often `0`). Consumer tests that compare `usage` with `toEqual` or snapshots may need updating.

New optional `requireApiKey` on `LlmGenerateOptions`: when true, a missing or blank `apiKey` throws `InvalidGenerateOptionsError` before any network call instead of silently falling back to the platform key (or Vertex ADC). The default behaviour is unchanged.
